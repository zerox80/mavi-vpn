# Mavi VPN 1.0.0 publication checklist

The GitHub release remains a draft until the release commit and distribution assets have been verified. The release body is maintained in `1.0.0.md` next to this file.

- [ ] Merge the version-preparation PR and confirm that the release target is the intended commit, including the P2 fixes.
- [ ] Verify the build, test, clippy, style, and security workflows for that exact commit.
- [ ] Download the four `Build Clients` artifacts (`linux-cli`, `linux-gui`, `windows-builds`, `android-apk`) from that commit. Do not reuse the locally staged 0.1.0 debug binaries.
- [ ] Attach the Windows installers and CLI/service bundle, Linux GUI and CLI packages, and clearly labelled Android APK. Keep `wintun.dll` with the standalone Windows binaries.
- [ ] Generate and attach `SHA256SUMS` for the exact distribution files.
- [ ] Smoke-test fresh installation, upgrade, connection, cancellation/reconnection, and removal on each supported platform.
- [ ] Decide whether Android is distributed as an explicitly labelled debug APK or a production-signed build. For production, configure a stable signing key and the verified HTTPS OAuth redirect/App Link; never label the existing debug output as production-signed.
- [ ] Update release-note links from `codex/release-1.0.0` to `1.0.0`, update the draft status paragraph to match the attached assets, and review the final text.
- [ ] Publish the release only after the above steps and the maintainer's publication decision.

The source version is `1.0.0` across Cargo, npm, Tauri, and Android. Android's `versionCode` advances from 1 to 2. Rust crates inherit the workspace version; the Linux CLI packaging job reads that version instead of maintaining a separate constant.
