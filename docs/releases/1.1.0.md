# Mavi VPN 1.1 — Packet memory and connection lifecycle improvements

Mavi VPN 1.1.0 improves packet memory ownership, HTTP/2 connection cleanup, and
Windows service IPC setup. It includes the server connection-setup hardening
introduced in 1.0.2.

## What's changed since 1.0.2

- **Bounded packet storage on the server:** Queued packets now own only their
  own bytes. A slow client can no longer retain a shared multi-megabyte buffer
  through a small queued packet. Queue capacity is reserved before allocating
  the packet copy.
- **HTTP/2 transport cleanup on Linux:** Dropping the final session handle stops
  its connection driver and capsule tasks. Failed or cancelled setup also stops
  the connection driver, preventing abandoned transport tasks from remaining
  active after disconnects or unsuccessful handshakes.
- **Less allocation in MASQUE framing:** CONNECT-IP datagram capsules are encoded
  directly into one correctly sized buffer, preserving the existing wire format.
- **Windows service IPC setup:** The service resolves the active console user's
  SID through Windows APIs instead of launching PowerShell for each lookup.
  Each lookup checks the current console session, including after user switching,
  and fails closed if a console user cannot be resolved.
- **Current transport forks:** The release lockfile is refreshed against the
  latest `zerox80/quinn` and `zerox80/h3` `main` branches and the `zerox80/h2`
  `master` branch. All seven fork packages remain branch-tracked.
- **Build dependencies:** Updated Rust, Android, and frontend dependencies,
  including Vitest 5 and Rust 1.98 Docker builder images.

## Upgrade notes

- Update the server for the packet-storage improvement, the Linux client for
  HTTP/2 task cleanup, and the Windows client/service for native console-user
  lookup. The capsule encoding remains compatible with the existing format.
- Windows clients still require a complete IPv6 tunnel configuration. Enable
  host IPv6 forwarding and set `VPN_DISABLE_IPV6=false` on the server before
  connecting Windows clients.
- Package versions are synchronized to `1.1.0` across the Rust workspace,
  desktop GUI, and Android app. Android's version code increases to `5`, above
  the `4` used by release 1.0.2.
- The existing Android CI produces a **debug APK**. A production Android release
  build requires a verified HTTPS OAuth App Link and a configured signing setup.
- The separate `mavi-vpn-docker` image follows `main`; its `latest` tag is not a
  versioned 1.1.0 image. Update that deployment with `docker compose pull` followed
  by `docker compose up -d` after a successful image publication.
